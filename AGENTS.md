# Project conventions

## Project goals and preservation principles

- Reduce the storage used by resources produced by Claude Code and Codex, including session history, temporary files, and other resources later confirmed safe to slim.
- When slimming sessions, prioritize preserving user-visible text, costs and token usage, timestamps, session/message/tool-call identities, relationships, and essential metadata needed for later tracing. Do not assume content has no preservation value merely because it occupies space.
- Duplicate, reconstructible, or unlikely-to-be-revisited content may be compacted or removed after verifying its format, references, and impact. Each operation must still comply with existing authorization, confirmation, and compatibility requirements.
- Verify "history remains queryable" and "the native client can resume and continue the session" separately. Reading JSONL or displaying text does not prove resumability. Prompt removal and similar approaches without verified resume support must not be described as resumable or automatically included in default slimming.
- The two basic safeguards are three-day protection and active-session protection: recently modified content follows the strict older-than-72-hours rule and explicit exceptions below. Sessions that are still open are always protected; being idle or temporarily producing no output does not mean they are closed.

## Cleanup commands

- Never automatically run cleanup commands, including Quick clean, deletion or compression from analysis, or cleanup preview commands.
- Run a cleanup command only when the user explicitly requests that operation. Feature implementation, development, testing, builds, and demonstrations do not authorize cleanup.

## Development conventions

- Always work on the `main` branch. Do not automatically switch branches or create worktrees.
- Use English for the application interface, help, error messages, and user-facing documentation. Preserve the original language of user paths and data.
- Keep the tool callable by agents: provide non-interactive arguments, stable JSON output, and exit codes. JSON mode must never show interactive prompts.
- Use `npm run test:read-only` for default verification. `npm test` includes cleanup and native deletion tests and must not run automatically without an explicit user request.

## Three-day protection (required for future iterations)

- All lossy or irreversible changes in Quick clean, automatic selection, and bulk operations (including deletion, inline image removal, tool-output compaction, removal of Codex encrypted reasoning state and old compaction snapshots, removal of Claude request archives, and compaction of successful hooks, tool definitions, and skill listings) may only affect content whose last modification time is strictly more than 72 hours before the current time. Use file `mtime`, not session creation time. Preserve recent files, files exactly 72 hours old, and files with future or invalid timestamps.
- The only age exception is when the user deliberately selects one specific file or one session without child sessions for an individual operation. Multi-selection, selecting an entire provider, a bulk scan yielding only one candidate, and `--yes` do not qualify. If expanding a session includes child sessions, apply bulk protection to the entire deletion scope; if any file in that scope is protected, skip the whole operation.
- Lossless PNG recompression that preserves image content and metadata is exempt from the age restriction. The single-target exception only waives age checks; existing format compatibility, activity, reference, integrity, and confirmation checks still apply.
- Exclude protected content during planning, omit it from estimated savings, and explain why it is retained. Recheck age and file state before execution. Do not introduce entry points or arguments that bypass this rule. Test age rules using in-memory metadata only, without running cleanup planners or executors.

## Active-session protection

- Do not delete or rewrite Claude Code / Codex sessions that are still open, or their associated resources. Single-target selection, an age over 72 hours, lossless compression, and `--yes` must not bypass active-session protection.
- Exclude active content from planning and estimates, omit it from estimated savings, and explain why it is retained. Recheck before execution and interrupted-operation recovery. Read-only analysis is not subject to this restriction.
- Detection must cover idle clients that have not closed. Do not infer that a session is closed merely because its file is not currently open, its mtime is unchanged, or it produces no output. Preserve content when activity cannot be checked reliably. If only the provider's running state can be confirmed and specific sessions cannot be reliably identified, conservatively retain that provider's candidate resources and explain the limitation.
- Test active-session protection using pure data, mocked process/open-file results, or disposable metadata fixtures. Do not run cleanup planners, executors, preview commands, or native resume/deletion probes.

## History slimming operations

- The user accepts that removing inline Base64 images makes the original images unavailable and that compacting command output makes omitted content unrecoverable. The user also accepts losing the ability to reconstruct exact historical API requests, successful hook commands/output/injected context, and historical tool definitions/skill listings, as well as potentially higher costs or missing non-critical context after resuming. The goal is to preserve traceability and the ability to continue chatting, without fully recreating the original context. This does not authorize actual cleanup during development.
- For both Claude Code and Codex, `Clean → Quick clean` includes `Remove inline images` and `Compact shell output` in estimates by default, alongside existing temporary-file cleanup and lossless PNG compression. Apply three-day and active-session protection, and wait for the user to press Enter before execution. Codex additionally includes `Remove encrypted reasoning (Codex)` and `Remove old compaction snapshots (Codex)` by default. Claude additionally includes `Remove API request archives (Claude)`, `Compact successful hooks (Claude)`, `Compact tool definitions (Claude)`, and `Compact skill listings (Claude)`. In the standalone `Clean → Slim history` flow, all options start unchecked and only operations supported by the selected provider are shown. The CLI enables history slimming through explicit `--remove-images` / `--compact-tools` / `--remove-reasoning` / `--remove-request-archives` / `--compact-hooks` / `--compact-tool-definitions` / `--compact-skill-listings` / `--remove-old-snapshots` flags.
- The fixed sequence is: scan, deep scan, show counts and estimated savings by operation (image removal, output compaction, and encrypted reasoning removal counted separately), show the total and irreversibility notice, then wait for the user to press Enter. Do not list individual files by default; retain full paths and per-file estimates in `View files` and JSON. In interactive mode, `--yes` must not skip Enter confirmation. Non-interactive and JSON modes execute with explicit `--yes` and must not prompt.
- Combine estimates across all selected providers and temporary directories, showing each operation and the total only once. Count image removal, lossless PNG compression, terminal-output compaction, Codex encrypted reasoning removal, old compaction snapshot removal, Claude request archive removal, successful hook compaction, tool definition compaction, skill listing compaction, and each temporary-file category separately. Do not double-count them in history slimming totals, and never display unknown estimates as zero.
- Remove Claude `api-request`, `api-request-shape`, and `api-request-blob` archives together only when independent conversation records exist and the entire archive family's structure is recognized. Preserve the whole family if any archive type or field is unknown. For successful hooks, clear only `command`, `content`, `stdout`, `stderr`, and any recorded `rendered` in recognized `hook_success` records with `exitCode=0`. Preserve the record's UUID, parentUuid, timestamp, status, and all other unchanged bytes. This hook operation preserves failed or unknown hooks, `prompt_snapshot`, instructions, and `skill_listing`. See the compatibility documentation for the boundaries of native validation and synthetic validation of combined operations.
- The user explicitly requested Claude tool definition and skill listing compaction as Quick clean defaults. For tool definitions, clear only recognized `prompt_snapshot.attachment.tools`, preserving system prompts. For skill listings, clear only recognized `skill_listing.attachment.content` and any recorded `rendered`, and reset `names` to `[]` and `skillCount` to `0` so stale discovery state does not suppress rediscovery. Complete the count updates even when they save no bytes. Preserve the entire record and its identity/relationship fields; retain unknown structures. Estimate the two operations separately and reuse protection, atomic replacement, and recovery flows. The limited native continuation evidence in the compatibility documentation does not establish coverage of all tools, MCP/plugins, or versions.
- Replace image blocks or compact successful command output according to verified provider formats. Preserve session/tool-call identities, signatures, relationships, and the original bytes of unchanged fields. Leave unrecognized, failed, or still-running output unchanged. Standalone plain or zstd legacy/paginated Codex JSONL may be slimmed, with coordinated updates to recognized SQLite byte offsets and cache entries using decoded JSONL bytes. Bound Codex slimming to 512 MiB stored and decoded, and 64 MiB per JSONL line; Claude slimming and Codex duplicate verification retain their 64 MiB file bounds. Hash and stage stored bytes, and measure compressed savings after recompression. Do not rewrite cross-rollout shared references or unknown offset structures until coordinated updates are implemented.
- Codex history slimming and regular/Quick clean deduplication may coordinate history at the same relative path and inode across the current user's `~/.codex`, Orca runtime home, and UUID account homes when all links can be accounted for. Include every discovered home in reference, activity, and SQLite offset/cache checks. All original and compressed aliases must be strictly older than 72 hours; the single-target age exception does not apply. Slimming replaces all aliases together. Deduplication first creates any missing compressed hard links, then removes original aliases, counting physical savings once. Receipts must record indexes across all homes, alias groups, and interruption state. Preserve originals until every index has committed and been verified; after interruption, verify and complete forward. Continue preserving actual cross-rollout references, independent copies, unknown links, and symbolic links. This support does not extend native whole-session deletion.
- Judge Claude Code and Codex history slimming, Claude whole-session deletion, and Codex temporary-file rules by actual structure, identity, and references. Do not block them solely because versions are unknown, missing, or mixed; preserve version fields unchanged. Cover format compatibility with synthetic tests and document it in `docs/native-compatibility.md`. Synthetic tests do not constitute native resume validation.
- Validate Codex native whole-session deletion against CLI capabilities and the deletion-scope contract, without an exact-version allowlist. Verify UUID/force/config support, disable the daemon and background history migration/compression, and bind the data directory. Capability checks do not prove native validation of every version. Check ownership and references in the first line of both plain and zstd history. Unrelated compressed files or hard links must not block an independent target; retain and explain the target's own unpreviewed copies, hard links, and shared references.
- Reuse atomic replacement and recovery mechanisms, revalidating preview hashes and file state before execution. Hold an index write transaction while replacing Codex JSONL; delete temporary originals only after successful index verification. Interrupted recovery must verify before/after hashes of originals and indexes and complete index updates, never blindly delete backups. Keep no undo copies after success, and state irreversibility in the preview.
- Codex reasoning removal deletes only non-empty string `encrypted_content` fields directly in `response_item.payload.type=reasoning`. Preserve summaries, content, signatures, IDs, compaction ciphertext, and nested replacement history. The removed reasoning state is unrecoverable; disclose this before confirmation.
- Codex old compaction snapshot cleanup removes only `replacement_history` and its accompanying `replacement_history_metadata` before the latest complete `compacted` record. Preserve the entire latest snapshot line, all summaries, ordinary chat, usage, and other unchanged bytes. Retain the file if the latest snapshot is missing or incomplete, any compaction record has an unknown structure, or rollback events are present. Shared references and unknown dependencies remain protected. Old snapshots are unrecoverable, and context when forking or rolling back to an earlier point may differ; disclose this before confirmation. Enable this by default in Quick clean, leave it unchecked in standalone Slim history, and require explicit `--remove-old-snapshots` in the CLI. Count items and savings separately and reuse index synchronization and recovery flows.
- Every new Codex history mutation must reuse the main flow coordinating JSONL, SQLite offsets/caches, and known associated dependencies, including estimation, execution, and interrupted recovery. Do not bypass it through ordinary deletion/compression entry points. Pending or recovering rewrites must carry `codexProjection`, explicitly set to an empty array when no indexes exist. Do not rewrite unknown dependencies or structures. Each extension must include the necessary index/cache handling, synthetic tests, and compatibility documentation updates. Whole-session deletion continues to use the native coordination path.
- Regular Codex cleanup and Quick clean include deduplication of matching `.jsonl` / `.jsonl.zst` pairs by default. Remove the original only when full decompression of all frames produces identical bytes, leaving the compressed version unchanged. Both files must be strictly older than 72 hours and inactive. Explicitly selecting the original does not waive age protection for the pair. Retain shared references, additional independent identity copies, links that cannot be coordinated under the protocol above, unknown dependencies, and corrupt streams. Reuse index transactions, receipts, and interrupted recovery; never take an ordinary file-deletion shortcut. Count the one physical original removed and its savings separately. Do not include deduplication in temporary-files-only or standalone history slimming modes.
- Read-only tests may use synthetic in-memory JSONL, in-memory SQLite, and temporary layout/receipt fixtures. This does not permit invoking cleanup planners, executors, cleanup preview commands, or native resume/deletion probes.

## System temporary files

- Quick clean and regular CLI clean may scan known system temporary layouts outside provider roots. Use explicit provider-specific file rules, current UID checks, and directory-permission checks, excluding configuration roots and the cc-clean state directory. Do not delete entire directories or infer deletability solely from `claude` / `codex` prefixes. Preserve source code, images, scratchpads, locks, sockets, and daemon data.
- External temporary files always require a strict age over 72 hours, with no explicit single-target age exception. Continue to show estimates by category, wait for Enter confirmation, recheck state, and use existing transactional recovery. Activity detection must check only candidate files, without recursively scanning the entire shared `/tmp`; statistics also count only matching files.
- Document layout sources and validation scope when extending temporary-file rules. Tests may only use disposable layouts for metadata scanning and pure-data receipt validation, without running cleanup planning, preview, execution, or recovery probes.

## RTK upstream code

- The user requested direct adoption of upstream RTK filtering logic. It is currently ported to TypeScript in `src/vendor/rtk.ts`, using only the Apache-2.0-licensed CLI `src/` code, excluding the BUSL-1.1 engine/proxy.
- Pin the upstream commit and record source functions, links, and modifications in `third_party/rtk/UPSTREAM.md`. Preserve copyright and modification notices, the complete LICENSE, and any applicable upstream NOTICE. Recheck each item when upgrading.
- The README must identify RTK as the source, its Apache-2.0 license, and the actual scope of the port. npm distributions must include `third_party/rtk/`. Do not describe selected filters as the complete RTK, and never rerun historical commands to obtain their output.
